Uchta narsa chiqadi: **backend**, **ilova** (`app.topagon.uz` ga ko'chadi),
**landing** (`topagon.uz` ni egallaydi).

> **VPS yo'llari** (2026-08-06 da tekshirilgan):
> backend — `/opt/topagon/backend`, foydalanuvchi — `root`.

> root allaqachon.

so'raydi, u esa hozirgi prodda **yo'q** (tekshirilgan: bo'sh javob).

## 1. Backend

Avval VPS'da qaysi compose fayli ishlayotganini aniqlang — buyruqlarning
qolgani shunga bog'liq:

```bash
cd /opt/topagon/backend
docker compose -f docker-compose.prod.yml ps
docker compose ps
```

Qaysi biri konteynerlarni ko'rsatsa — o'shanikini ishlating. Quyida
`docker-compose.prod.yml` deb yozilgan; agar sizda oddiy `docker-compose.yml`
ishlayotgan bo'lsa, `-f docker-compose.prod.yml` qismini olib tashlang.

Windows'da (kod ko'chirish):

```powershell
cd "D:\platform edu"
ssh root@VPS_IP "mkdir -p /opt/topagon/backend-new"
scp -r backend\app backend\sql backend\scripts backend\deploy `
    root@VPS_IP:/opt/topagon/backend-new/
```

VPS'da:

```bash
cd /opt/topagon/backend

# Zaxira — migratsiya oldidan doim
docker compose -f docker-compose.prod.yml exec -T db \
    pg_dump -U edu -d edu -Fc -f /tmp/pre-021.dump
docker compose -f docker-compose.prod.yml cp db:/tmp/pre-021.dump ./pre-021.dump

# Yangi kodni joyiga qo'yish
rsync -a --delete /opt/topagon/backend-new/app/     /opt/topagon/backend/app/
rsync -a          /opt/topagon/backend-new/sql/     /opt/topagon/backend/sql/
rsync -a          /opt/topagon/backend-new/scripts/ /opt/topagon/backend/scripts/
rsync -a          /opt/topagon/backend-new/deploy/  /opt/topagon/backend/deploy/

# CORS: ilova endi app.topagon.uz da. Prod guard `*` ni qabul qilmaydi.
sed -i 's|^CORS_ORIGINS=.*|CORS_ORIGINS=https://app.topagon.uz|' .env
grep CORS_ORIGINS .env

# `restart` EMAS — u Python kodini qayta yuklamaydi
docker compose -f docker-compose.prod.yml up -d --build api

# Migratsiya: avval nima kutayotganini ko'r
./scripts/migrate.sh --status
./scripts/migrate.sh          # 021_user_avatar.sql qo'llanadi
./scripts/migrate.sh --status # endi "applied" bo'lishi kerak
```

Tekshiruv — uchalasi ham javob berishi shart:

```bash
curl -s https://api.topagon.uz/health
curl -s https://api.topagon.uz/v1/auth/methods
# {"phone":false,"telegram":true,"invite":true,"telegram_bot_username":"topagonuzbot"}

docker compose -f docker-compose.prod.yml exec -T db \
    psql -U edu -d edu -c "\d users" | grep avatar_color
```

`/v1/auth/methods` hali bo'sh qaytsa — konteyner eski image bilan turibdi.
`docker compose -f docker-compose.prod.yml logs --tail 60 api` ga qarang.

## 2. Ilova (Flutter Web) → app.topagon.uz

Windows'da:

```powershell
cd "D:\platform edu\mobile"
flutter pub get          # flutter_animate yangi paket
flutter gen-l10n
flutter analyze          # toza bo'lishi kerak

flutter build web --release --pwa-strategy=none `
  --dart-define=API_BASE_URL=https://api.topagon.uz `
  --dart-define=WEB_BASE_URL=https://app.topagon.uz

ssh root@VPS_IP "mkdir -p /opt/topagon/app-build"
scp -r build\web\* root@VPS_IP:/opt/topagon/app-build/
```

`WEB_BASE_URL` ni unutmang: bellashuv havolasi (`?join=KOD`) shu domendan
quriladi. Eski qiymat qolsa havola reklama sahifasiga olib boradi.

**`--pwa-strategy=none` ham unutmang.** Usiz Flutter service worker yaratadi
va u ilovani keshlab qo'yadi — sinovchilar yangi versiyani KO'RMAYDI, hatto
`Ctrl+Shift+R` bosishsa ham. Tafsilot: `mobile/web/flutter_service_worker.js`
faylining boshidagi izoh.

VPS'da:

```bash
mkdir -p /var/www/topagon-app
rsync -a --delete /opt/topagon/app-build/ /var/www/topagon-app/
chown -R www-data:www-data /var/www/topagon-app
```

## 4. nginx + sertifikat

```bash
cd /opt/topagon/backend

# Hozir qaysi sayt yoqilganini ko'ramiz — nom boshqacha bo'lishi mumkin
ls -l /etc/nginx/sites-enabled/

# Landing apex domenni egallaydi (eski web config o'chadi).
# Yuqoridagi ro'yxatda ko'rgan nomni yozing — `topagon-web` bo'lmasligi mumkin.
rm -f /etc/nginx/sites-enabled/topagon-web

cp deploy/nginx-landing.conf /etc/nginx/sites-available/topagon-landing
cp deploy/nginx-app.conf     /etc/nginx/sites-available/topagon-app
ln -sf /etc/nginx/sites-available/topagon-landing /etc/nginx/sites-enabled/
ln -sf /etc/nginx/sites-available/topagon-app     /etc/nginx/sites-enabled/

nginx -t
```

`nginx -t` `app.topagon.uz` sertifikati yo'qligidan shikoyat qiladi — bu
kutilgan. Sertifikat olamiz:

```bash
# 443-blokni vaqtincha izohga olamiz, aks holda certbot nginx'ni ko'tara olmaydi
certbot --nginx -d app.topagon.uz --non-interactive --agree-tos \
     -m zayniddin686@gmail.com

nginx -t && systemctl reload nginx
```

Tekshiruv:

```bash
curl -sI https://topagon.uz     | head -1   # 200
curl -s  https://topagon.uz     | grep -o "HAR BIR SAVOL"
curl -sI https://app.topagon.uz | head -1   # 200
curl -s  https://app.topagon.uz | grep -o "flutter_bootstrap"
```

## 6. Orqaga qaytarish

Bir narsa buzilsa:

```bash
# nginx: eski holat
rm -f /etc/nginx/sites-enabled/topagon-landing /etc/nginx/sites-enabled/topagon-app
ln -sf /etc/nginx/sites-available/topagon-web /etc/nginx/sites-enabled/
systemctl reload nginx

# baza: migratsiyadan oldingi nusxa
docker compose -f docker-compose.prod.yml cp ./pre-021.dump db:/tmp/r.dump
docker compose -f docker-compose.prod.yml exec -T db \
    pg_restore -U edu -d edu --clean --if-exists /tmp/r.dump
```

`021_user_avatar.sql` faqat ustun qo'shadi (`ADD COLUMN IF NOT EXISTS`) —
eski kod u ustunni bilmaydi, lekin xato ham bermaydi. Ya'ni backend'ni
orqaga qaytarish uchun bazani tiklash SHART EMAS.
